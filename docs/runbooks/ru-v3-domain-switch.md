## Переходное поведение

- Основные страницы `.ru` открываются непосредственно. Обычные GET/HEAD на прежнем адресе временно переходят на `.ru` с тем же путём и параметрами. Вебхуки и API используют прямые маршруты.
- Проверь старые ссылки регистрации, восстановления, гостевого доступа и командных приглашений. Старые cookie, PKCE и локальный черновик профиля принадлежат своему хосту. Убедись, что ограниченные маршруты завершения дают воспользоваться ещё действующей ссылкой или штатно получить новую на `.ru`. Для перехода в новый кабинет используй повторный вход и серверные данные.
- Ссылки в новых страницах и PDF используют `.ru`. Проверь новый экземпляр каждого PDF и скачивание ранее выданных. [Черновик оферты v3](../legal/drafts/advanced-terms-ru-v3.md) меняет адрес сайта. Публикация новой редакции проходит по действующей процедуре согласования.

## Рабочее переключение

1. Запиши текущие значения и ревизии обеих служб, рабочие настройки Auth и активных интеграций. Сверь DNS, сертификаты, журнал миграций и точку восстановления. Проверь точный коммит с приложением и изолированной PostgreSQL. В пакет входит также `20261115181246_yookassa_checkout_return_origin.sql`, которая сохраняет адрес возврата для нового рабочего платежа.
2. Добавь точные callback `.ru` в рабочий Supabase. Примени проверенные миграции из согласованного пакета RU-3. Методика v5 остаётся `draft` до проверки совместимых служб.
3. Обнови веб-сервис и обработчик очереди до одного проверенного коммита. В согласованном окне установи новый `APP_URL` у обеих служб и новый Site URL. При активном платёжном контуре переключи прямой webhook по согласованному списку событий. Убедись, что прежний endpoint принимает переходящие уведомления с HTTP 200. Проверь, что незавершённая оплата использует записанный адрес возврата. Для рабочих заказов, созданных до новой миграции, используется прежний адрес `.com`.
4. Проверь обе цепочки перехода, открытие кабинета, повторный вход, завершение старых ссылок, профили, отчёты и очередь. Для платежей используй контролируемые тестовые сценарии. Проверь `.ru` и загрузку ресурсов диктовки из сети в России без VPN либо укажи дату и сеть, для которой доступ подтверждён.
5. Включи v5 для новых прохождений отдельным шагом. Проверь 93 вопроса в новом русском запуске и старый черновик v4. Проверь обычные приглашения с новым 24-часовым сроком.

## Откат

Верни `APP_URL`, Site URL, активные шаблоны и настройки callback/webhook к записанным значениям. Повтори проверку рабочего сайта, входа, существующих ссылок и обработчика. Сохрани совместимый код для отчётов и начатых прохождений v5. После появления заказов с новым адресом возврата откатывай настройки на коммите, который читает сохранённый адрес заказа. Для остановки назначения v5 используй отдельную процедуру из [плана RU-3](./ru-v3-staging.md#откат) с учётом необратимости `retired`.
