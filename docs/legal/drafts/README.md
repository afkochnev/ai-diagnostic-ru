# Точные тексты для окончательного рассмотрения владельцем

Статус всех трёх текстов: **DRAFT / НЕ УТВЕРЖДЕНЫ / НЕ ОПУБЛИКОВАНЫ**. Принята только структура пакета и mapping. Чистые тела ниже предложены для последующей публикации; отсутствие watermark внутри тела не является утверждением или публикацией.

- [Политика](data-processing-policy-ru-v1.md)
- [Согласие на обработку данных](data-processing-consent-ru-v1.md)
- [Отдельное маркетинговое согласие](marketing-consent-ru-v1.md)

Точные SHA256 тел (UTF-8, включая финальный LF) записаны в docs/v27-legal-package.json и artifacts/v27-production-launch/privacy-finalization/legal-final-hashes.json. Утверждение требуется для этих конкретных текстов/хешей. Оно не получено. Дата вступления в силу определяется будущей публикацией; сейчас эти документы не действуют. В public.privacy_legal_documents нет опубликованных строк, current consent pointers остаются temporary-ru-v1.

На staging проверены ограниченная очистка временных anonymous payloads, событий старше 12 месяцев, минимизация email delivery logs и технический отзыв маркетинга. Расписания нет: очистку ограниченными порциями запускает оператор по docs/runbooks/v27-retention-maintenance.md. Существующие staging данные не удалялись; проверка выполнялась только на новых synthetic fixtures. Автоматическая очистка Team по возрасту не применяется.

Запрос на удаление Account/данных обрабатывается вручную по docs/runbooks/v27-data-deletion-request.md. Это готовая процедура, а не утверждение, что удаление настоящего аккаунта уже выполнялось. Поставщики и резервные копии требуют отдельного контроля; store:false не доказывает Zero Data Retention. Новый массовый сбор согласий при входе не предусмотрен. Прежние версии и consent records неизменяемы.

OWNER_ACCEPTED_RU_DATA_LOCALIZATION_RISK остаётся неблокирующим принятым риском, а не подтверждением полного юридического соответствия. Supabase, Render, OpenAI, Resend и YooKassa описаны согласно фактической обработке; утверждения о хранении всех данных в России нет.
